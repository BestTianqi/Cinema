# 智能影院选座系统 —— 实现思路文档

---

## 一、项目概述

### 1.1 项目背景

电影院选座不仅仅是技术问题，更是一个融合用户体验、交互设计、行为心理学和产品设计的综合性课题。不同用户群体——大学生、情侣、家庭、老年人、团体观众——对选座有着截然不同的需求。传统的电影院选座界面往往只提供一个静态的座位图，让用户自行判断和选择，这导致用户决策成本高、选座效率低、观影体验差。

本项目的目标是设计并开发一个**智能影院选座系统**，通过智能推荐算法、可视化热度地图、观影体验评分等核心功能，帮助用户快速找到最合适的座位，降低决策成本，提升购票效率和观影体验。

### 1.2 核心目标

- **快速决策**：通过智能推荐，帮助用户在 3 步内完成选座
- **降低决策成本**：系统主动推荐，减少用户思考和比较的时间
- **提升观影体验**：基于视角、距离等多维度评分，推荐最佳观影位置
- **提高购票效率**：简化操作流程，支持快捷选座操作
- **全人群覆盖**：针对大学生、情侣、家庭、老年人、团体提供差异化体验

### 1.3 设计原则

本项目严格遵循 **"Don't Make Me Think"（别让用户思考）** 原则，核心理念是：系统应该主动替用户思考，而非让用户在复杂的座位图中自行判断。具体体现为：

1. **智能推荐优先**：用户进入页面后，系统自动推荐最佳座位
2. **最少操作步骤**：选座流程控制在 ≤3 步
3. **视觉直觉化**：用颜色、图标、动画传达信息，减少文字阅读
4. **容错与引导**：用户操作错误时友好提示，并引导正确操作

### 3.2 设计模式选择

本项目采用**组件化 + 状态管理**的架构模式，虽然不引入框架，但通过原生JavaScript模拟组件化思想：

```
核心设计模式：
1. 发布-订阅模式（Pub-Sub）：座位状态变化 → 通知各模块更新
2. 策略模式（Strategy）：不同用户类型的推荐策略
3. 观察者模式（Observer）：数据层变化自动触发UI重绘
```

### 3.4 数据流设计

```
用户操作 → 事件触发 → 状态更新 → 事件通知 → UI重绘

具体流程：
1. 用户点击"智能推荐"按钮
2. recommendPanel.js 收集用户输入（每位成员姓名+年龄、人数、观影类型）
3. 调用 recommendEngine.js 计算最佳座位
4. 更新 seatData.js 中的座位状态
5. eventBus.js 发布 "seats:updated" 事件
6. canvasRenderer.js 监听到事件，重绘座位颜色
7. scorePanel.js 监听到事件，更新评分显示
```

#### Step 1.2：创建影厅配置数据

**做什么**：
- 定义影厅的座椅布局参数（多少排、每排多少座、过道位置）

**思路要点**：
- 影厅配置建议：12排 × 18列 = 216个座位（可根据银幕大小调整）
- 中间留2条过道（第6列后、第12列后各一条），模拟真实影院

- 每排座位数可能不同（梯形布局，靠近银幕的前排座位数略少）
- 座位状态初始化为`available`，后续根据"已售"数据更新

**数据结构设计思路**：
```
问自己：每个座位需要哪些属性？
- id: 唯一标识（如"F-08"表示F排8号座）
- row: 第几排
- col: 第几列
- x, y: 在Canvas上的坐标位置（运行时计算）
- status: 当前状态
- score: 观影体验评分（运行时计算）

思考：哪些是静态数据（配置），哪些是动态数据（运行时状态）？
- 静态：行列数、过道位置、银幕大小
- 动态：座位状态、评分、热度
```

### 第二阶段：Canvas影院平面图绘制（2-3天）

#### Step 2.1：绘制基础影院布局

**做什么**：
- 使用Canvas绘制银幕（屏幕上方的大弧形或矩形）
- 绘制座位网格（用圆角矩形或圆形表示每个座位）
- 绘制排号标签（左侧A、B、C...）和座位号标签
- 绘制过道（座位之间的空白间隔）
- 添加"银幕"文字标识

**思路要点**：

**1. Canvas尺寸计算**：
- 先在JS中动态设置Canvas的width/height属性（不是CSS的width/height）
- Canvas内部分辨率 = 设备像素比 × CSS显示尺寸（处理Retina屏幕）
- 推荐做法：
  ```javascript
  const dpr = window.devicePixelRatio || 1;
  canvas.width = canvas.clientWidth * dpr;
  canvas.height = canvas.clientHeight * dpr;
  ctx.scale(dpr, dpr);
  ```

**2. 银幕绘制**：
- 银幕位于Canvas顶部，用梯形或带弧度的矩形表示
- 使用渐变色填充（`createLinearGradient`），营造科技感
- 银幕下方留一定间距再开始第一排座位

**3. 座位绘制**：
- 每个座位用一个小矩形或圆形表示
- 座位之间保持合理间距（推荐 seatGap = 4-6px）
- 可选用圆角矩形（`roundRect`）或圆形（`arc`）
- 不同状态的座位用不同颜色：
  - 可选（available）：浅灰/浅蓝
  - 已推荐（recommended）：高亮色（如金色/亮蓝）
  - 已选中（selected）：确认色（如绿色）
  - 已售出（sold）：深灰/不可用色

**4. 响应式座位大小**：
- PC端座位可以大一些（如22×22px）
- 手机端座位缩小（如14×14px），但需保证可点击的最小触摸面积（≥44×44px逻辑区域）
- 思路：定义一个`getSeatSize()`函数，根据屏幕宽度返回座位尺寸

#### Step 3.1：实现座位点击命中检测

**做什么**：

- 编写`hitTest(x, y)`函数，判断用户点击/触摸的位置对应哪个座位
- 处理Canvas坐标转换（考虑设备像素比、滚动偏移）

**思路要点**：

**命中检测的核心思路**：
```
每个座位在Canvas上有自己的绘制区域（boundingBox），
当用户点击Canvas时：
1. 获取鼠标在Canvas上的坐标(mouseX, mouseY)
2. 遍历所有座位，检查(mouseX, mouseY)是否在某个座位的boundingBox内
3. 如果在，返回该座位对象；如果不在，返回null

优化思路：不用每次遍历所有座位
- 先根据mouseY除以行高快速定位到是哪一排
- 再在该排内根据mouseX除以列宽快速定位到是哪一列
- 这样从O(n)降到O(1)
```

**Canvas坐标转换注意事项**：
```javascript
function getCanvasCoords(e) {
  const rect = canvas.getBoundingClientRect();
  const scaleX = canvas.width / (canvas.clientWidth * dpr);  // 内部坐标与显示坐标的比例
  const scaleY = canvas.height / (canvas.clientHeight * dpr);
  return {
    x: (e.clientX - rect.left) * scaleX,
    y: (e.clientY - rect.top) * scaleY,
  };
}
```

**热度计算考虑的因素**：

2. **历史选座频率**：模拟过去一段时间的选座记录

```javascript
// 如果没有真实数据，用算法模拟
function calculateHeatLevel(seat) {
  let heat = 0;
  
  // 中央位置加分（高斯分布：越靠近中间列越高）
  const centerCol = hallConfig.cols / 2;
  heat += gaussian(seat.col, centerCol, 4) * 40;
  
  // 排数加分（中间排最高）
  const optimalRow = hallConfig.rows * 0.5; // 中间排
  heat += gaussian(seat.row, optimalRow, 2.5) * 40;
  
  // 观影评分贡献
  heat += seat.score * 0.2;
  
  // 归一化到 1-3 等级
  return heat > 60 ? 3 : heat > 30 ? 2 : 1;
}

// 高斯函数
function gaussian(x, mean, stdDev) {
  return Math.exp(-((x - mean) ** 2) / (2 * stdDev ** 2));
}
```

### 第六阶段：观影体验评分（2-3天）

#### Step 6.1：评分模型设计

**做什么**：
- 设计多维度评分体系
- 实现视角、距离、周围空位的量化计算
- 综合评分并分为"极佳"、"优秀"、"一般"三档

**思路要点**：

**评分维度与权重**：

| 评分维度 | 权重 | 计算方式 | 说明 |
|---------|------|---------|------|
| 视角偏差 | 35% | 座位与银幕中心线的水平偏移角度 | 越正对银幕越佳 |
| 观影距离 | 30% | 座位到银幕的视觉距离 | 太近太远都不好 |
| 水平位置 | 15% | 座位在排内的水平位置（中央优先） | 中间优于两侧 |
| 周围空位 | 20% | 周围8个邻座中空位占比 | 周围越空体验越好 |

**视角计算思路**：
```
假设银幕中心在坐标系中的位置为 (screenCenterX, screenCenterY)
座位位置为 (seatX, seatY)

1. 水平偏移角：座位与银幕中心的水平夹角
   angle = atan2(|seatX - screenCenterX|, seatY - screenCenterY)
   角度越小 = 越正对银幕 = 评分越高

2. 评分映射（角度越小分越高）：
   0° → 100分, 30° → 70分, 60° → 30分, >80° → 0分
```

**距离评分思路**：
```
观影最佳距离 ≈ 银幕宽度的 1.5~2.5 倍
距离过近：脖子累，视角太大
距离过远：看不清细节

距离分 = 基于最佳距离区间的高斯分布
距离正好在最佳区间 → 满分
偏离最佳区间越远 → 分越低
```

**综合评分**：
```javascript
function calculateScore(seat) {
  const angleScore = calcAngleScore(seat);      // 视角分 0-100
  const distanceScore = calcDistanceScore(seat); // 距离分 0-100
  const centerScore = calcCenterScore(seat);     // 位置分 0-100
  const emptyScore = calcEmptyScore(seat);       // 空位分 0-100

  const totalScore = 
    angleScore * 0.35 +
    distanceScore * 0.30 +
    centerScore * 0.15 +
    emptyScore * 0.20;

  // 评级
  const grade = totalScore >= 80 ? '极佳' : totalScore >= 60 ? '优秀' : '一般';
  
  return { totalScore, grade, details: { angleScore, distanceScore, centerScore, emptyScore } };
}
```

### 第九阶段：响应式布局（2天）

#### Step 9.1：CSS响应式设计方案

**做什么**：
- 使用CSS媒体查询适配PC、iPad、手机
- Canvas尺寸自适应
- 面板布局在移动端重新排列

**思路要点**：

**断点设计**：
```css
/* PC端 (>=1024px)：Canvas在中间，两侧面板 */
/* iPad端 (768-1023px)：Canvas在上方，面板在下方 */
/* 手机端 (<768px)：Canvas全宽，面板在底部弹出或折叠 */
```

**布局策略**：
- PC：三栏布局 — 左侧推荐面板 | 中间Canvas | 右侧订单面板
- iPad：两栏布局 — 上部Canvas | 下部功能面板（Tab切换）
- 手机：单栏布局 — Canvas全屏 | 底部弹出面板

**Canvas响应式**：
```javascript
function resizeCanvas() {
  const container = document.getElementById('canvas-container');
  const width = container.clientWidth;
  const height = Math.min(width * 0.7, window.innerHeight * 0.7);
  
  canvas.style.width = width + 'px';
  canvas.style.height = height + 'px';
  canvas.width = width * dpr;
  canvas.height = height * dpr;
  ctx.scale(dpr, dpr);
  
  // 重新计算座位坐标
  recalculateSeatPositions();
  redraw();
}

window.addEventListener('resize', debounce(resizeCanvas, 200));
```

**移动端优化**：
- 座位大小最小14px，但hitArea扩大到44px（保证可点击）
- 触摸事件处理（touchstart、touchend）
- 禁用双击缩放
- 横屏时Canvas全屏展示

## 六、关键技术难点与解决方案

### 难点1：Canvas命中检测的性能与准确性

**问题**：座位很多（200+），每次点击都要遍历所有座位做碰撞检测，如果逻辑写得不好会导致卡顿。同时，在Retina屏幕和缩放情况下坐标转换容易出错。

**解决方案**：
- 使用空间索引优化命中检测：先通过行列快速定位候选座位，而非全量遍历
- 规范化坐标转换函数，统一处理DPR和滚动偏移
- 移动端touch事件绑定在Canvas上时，注意`e.preventDefault()`防止页面滚动

---

### 难点2：推荐引擎的灵活性与可扩展性

**问题**：推荐规则可能会不断调整（新增用户类型、调整偏好参数），如果写成硬编码的if-else，后期维护会很痛苦。

**解决方案**：
- 使用规则引擎模式：规则 = 条件函数 + 动作函数 + 优先级
- 将规则写在数组中，方便增删改
- 将权重参数抽取到config.js中，方便调参

---

### 难点3：Canvas重绘性能

**问题**：每次用户交互（hover、点击、选中）都触发整个Canvas重绘，如果座位多、动画多，可能出现掉帧。

**解决方案**：
- 使用`requestAnimationFrame`控制重绘频率
- 对于hover这种高频事件，使用"脏标记"策略：
  - 状态变化时只标记为"需要重绘"
  - 在rAF回调中统一执行一次重绘
  - 避免同一帧内多次重绘
- 如果座位数量确实很大（500+），可考虑离屏Canvas（offscreen canvas）做缓存

---

### 难点4：响应式与Canvas的内在冲突

**问题**：CSS可以响应式地改变元素大小，但Canvas是固定分辨率的位图。如果Canvas的CSS尺寸变了但width/height属性没变，画面会模糊；如果重新设置width/height，所有内容都要重新绘制。

**解决方案**：
- 窗口resize时：重新设置canvas.width/height → 重新计算所有坐标 → 重新绘制
- 使用debounce(200ms)防止resize事件过于频繁
- 提取坐标计算逻辑为独立函数，resize时只需调用一次

---

### 难点5：多模块状态同步

**问题**：推荐引擎、手动选座、订单管理都会修改座位状态。如何保证各模块看到的状态是一致的？

**解决方案**：
- 使用事件总线（EventBus）作为模块间通信的唯一通道
- 座位状态集中管理在seatData.js中
- 任何模块修改座位状态 → 通过EventBus通知 → 其他模块响应
- 单向数据流：数据变化 → 通知UI更新，而非UI直接操作其他UI

## 八、给每一步的核心建议

### 给成员A（项目经理 & 推荐引擎）

1. **先设计规则表，再写代码**：在纸上或文档中梳理清楚每种用户类型的偏好规则，得到团队确认后再编码
2. **规则要可配置**：不要写死"前三排"，而是定义`frontRowsToAvoid: 3`这样的变量
3. **推荐理由文案化**：推荐结果不只是高亮座位，还要有文字说明，这对用户信任度非常重要
4. **AI开发说明书**：每次用AI生成代码或文案后立即记录，不要最后才赶

### 给成员B（UX设计 & 热度地图）

1. **先出色彩方案**：在写代码之前，先用Figma或在线调色板确定配色，得到团队一致认可
2. **热度计算先模拟数据验证**：用Excel或写个小脚本生成热度数据，确认红黄绿分布合理
3. **Canvas渐变要微调**：红→黄→绿的渐变直接做会很生硬，中间需要过渡色
4. **参考但不抄袭**：参考Apple、Tesla的官网风格是可以的，但要融入自己的理解

### 给成员C（交互设计 & 手动选座 & 无障碍）

1. **先画流程图**：用纸或draw.io画出所有用户操作的流程图，确认没有遗漏的交互状态
2. **选座交互先做对再做快**：先实现基础单选，确认命中检测准确无误，再做多选和拖拽
3. **Canvas事件坐标转换要仔细**：这是最容易出Bug的地方，建议写单元测试式的console验证
4. **无障碍不只是切换颜色**：大字体模式要测试所有文字是否都能放大而不溢出；高对比度模式要保证所有交互元素都可见

### 给成员D（架构师 & 评分引擎 & 订单中心）

1. **先定接口再写实现**：和其他成员明确模块间的调用方式（函数名、参数、返回值），写在一个共享文档里
2. **评分公式先用Excel验证**：在Excel里建一个座位评分表，验证公式对不同位置座位的评分是否符合直觉
3. **LocalStorage封装要加try-catch**：LocalStorage可能因为容量满或隐私模式而不可用
4. **响应式不要最后才做**：从第一行CSS代码就考虑响应式，用相对单位和CSS变量

## 九、常见坑与避坑指南

1. **Canvas坐标陷阱**：Canvas的`width/height`属性（内部分辨率）和CSS的`width/height`（显示尺寸）是两回事。混淆会导致画面模糊或坐标偏移。**正确做法**：始终`canvas.width = clientWidth * dpr`。

2. **移动端300ms延迟**：移动端click事件有300ms延迟。**解决方案**：使用`pointerdown`事件替代`click`，或使用`touch-action: manipulation` CSS属性。

3. **LocalStorage容量限制**：大多数浏览器限制5MB。座位和订单数据量小，一般够用，但要注意不要存储冗余数据。只存储差异数据（哪些座位被订），全量座位配置存JSON文件。

4. **模块耦合过紧**：如果所有代码都写在main.js里，后期修改会很痛苦。**解决方案**：严格遵守模块化设计，每个JS文件只做一件事，通过EventBus通信。

5. **推荐算法过于复杂**：刚开始不要追求完美的推荐算法。先用简单的规则if-else实现，保证能跑通，再逐步优化。

6. **忽略边界情况**：
   - 所有座位都满了怎么办？
   - 情侣想坐一起但只剩单个空位了怎么办？
   - 团体(20人)找不到同排连续座位怎么办？
   - 这些边界情况需要在设计时就想好处理方案

7. **只考虑桌面端**：项目要求PC、iPad、手机端。从开发的第一天就要用浏览器的设备模拟器在不同屏幕尺寸下查看效果。

## 十、总结

本项目是一个综合性很强的Web前端项目，涵盖了**产品设计、UX设计、交互设计、前端工程化**等多个维度。成功的关键在于：

1. **理解用户**：不是为自己写代码，是为五种不同类型的用户设计体验
2. **模块化开发**：六个人功能模块独立但数据联动，需要良好的架构设计
3. **Canvas是核心**：建议团队每个人都花时间理解Canvas的绘图和交互机制
4. **先跑通再优化**：MVP（最小可行产品）优先，先实现基本功能链，再打磨细节
5. **文档是交付物的一部分**：不只是代码，AI开发说明书、设计文档、操作流程图同样是评分依据

记住核心原则——**Don't Make Me Think**。当你纠结于某个交互设计时，问自己：用户会困惑吗？这个操作够不够直觉？有没有更好的方式让用户不用思考就能完成操作？
